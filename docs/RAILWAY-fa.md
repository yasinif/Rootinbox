# راهنمای استقرار سریع RootInbox در Railway (Zero-Config)

این راهنما نحوه استقرار نسخه آماده RootInbox را روی پلتفرم Railway با حداقل مراحل (کمتر از ۵ دقیقه) و بدون نیاز به تعریف دستی متغیرهای محیطی پیچیده شرح می‌دهد.

---

## مراحل استقرار (۵ مرحله ساده)

### مرحله ۱: ایجاد پروژه در Railway
۱. وارد حساب کاربری خود در [Railway.com](https://railway.com) شوید.
۲. دکمه **New Project** را بزنید و گزینه **Deploy from GitHub repo** را انتخاب کنید.
۳. مخزن RootInbox را انتخاب کنید.

### مرحله ۲: افزودن دیسک ذخیره‌سازی دائمی (Volume)
> [!IMPORTANT]
> برای اینکه پایگاه داده SQLite و کلیدهای تولیدشده پس از هر ری‌استارت یا دیپلوی مجدد حفظ شوند، افزودن Volume الزامی است.

۱. در صفحه پروژه روی سرویس کلیک کنید و وارد تب **Settings** شوید.
۲. بخش **Volumes** را پیدا کرده و روی **Add Volume** کلیک کنید.
۳. مسیر مونت (Mount Path) را دقیقا برابر `/data` قرار دهید.

### مرحله ۳: استقرار اولیه (Deploy)
پروژه به صورت خودکار با استفاده از Dockerfile ساخته و اجرا می‌شود. برنامه مسیر `/data` را شناسایی کرده و فایل `secrets.json` و دیتابیس را به طور امن ایجاد می‌کند.

### مرحله ۴: تولید دامنه اختصاصی (Generate Domain) و استقرار مجدد (Redeploy)
۱. در صفحه سرویس به تب **Settings** بروید و به بخش **Networking** مراجعه کنید.
۲. روی گزینه **Generate Domain** کلیک کنید تا یک دامنه عمومی (مانند `your-app.up.railway.app`) به سرویس اختصاص داده شود.
۳. **نکته بسیار مهم:** تولید دامنه در Railway صرفاً لایه مسیریابی لبه (Edge Proxy) را تنظیم می‌کند و کانتینر در حال اجرا را مجدداً مستقر نمی‌کند. برای اینکه متغیر `RAILWAY_PUBLIC_DOMAIN` به محیط کانتینر تزریق شود، در تب **Deployments** روی منوی سه‌نقطه دیپلوی فعال کلیک کرده و گزینه **Redeploy** (یا Restart) را انتخاب نمایید.
۴. پس از بالا آمدن مجدد، برنامه متغیر `RAILWAY_PUBLIC_DOMAIN` را به طور خودکار شناسایی کرده و مبدأ مجاز (Origin) و اتصالات وب‌سوکت را پیکربندی می‌کند.

### مرحله ۵: دریافت توکن مدیریت اولیه (Admin Key)
۱. در تب **Deployments** روی دیپلوی فعال کلیک کرده و وارد بخش **View Logs** شوید.
۲. در لاگ‌های راه‌اندازی اولیه، خطی مشابه زیر را مشاهده خواهید کرد:
   ```
   ================================================================================
   ROOTINBOX INITIAL ADMIN SETUP TOKEN (SHOWN ONCE)
   Token: rootinbox_adm_...
   Save this token securely! It is required for administrative API access.
   ================================================================================
   ```
۳. این توکن فقط یک‌بار نمایش داده می‌شود و فقط هش SHA-256 آن ذخیره شده است. آن را در جای امن یادداشت کنید.

حالا می‌توانید آدرس دامنه خود را در مرورگر باز کنید و از RootInbox استفاده نمایید!

## عیب‌یابی و پرسش‌های متداول (Troubleshooting)

### خطای «Waiting for Domain» در مرورگر
- **علت:** سرویس اجرا شده اما هنوز در تب Networking روی دکمه Generate Domain کلیک نکرده‌اید، یا پس از کلیک روی دکمه، کانتینر را Redeploy نکرده‌اید تا متغیر محیطی دامنه فعال شود.
- **راه‌حل:** در بخش Networking دکمه Generate Domain را بزنید و سپس سرویس را Redeploy کنید، یا در صورت استفاده از دامنه سفارشی، متغیر `APP_ORIGIN=https://your-custom-domain.com` را اضافه نمایید (تعریف متغیر به طور خودکار باعث دیپلوی مجدد می‌شود).

### هشدار «Ephemeral storage detected» در لاگ‌ها
- **علت:** دیسک ذخیره‌سازی دائمی (Volume) به سرویس متصل نشده است و داده‌ها با هر بار استقرار پاک خواهند شد.
- **راه‌حل:** طبق مرحله ۲، یک Volume در مسیر `/data` به سرویس اضافه کنید.

### بازنشانی توکن ادمین (Admin Key)
اگر توکن ادمین را گم کرده‌اید:
۱. از طریق Railway CLI دستور زیر را اجرا کنید:
   ```bash
   railway run ./rootinbox admin reset-key
   ```
   یا متغیر محیطی زیر را موقتا در Railway تعریف کرده و ذخیره کنید:
   ```
   ADMIN_TOKEN_HASH=<sha256_hex_of_your_new_password>
   ```

### خطای امنیتی پایگاه داده موجود بدون کلید («existing database found but secrets file missing»)
- **علت:** پایگاه داده وجود دارد اما فایل `secrets.json` در Volume حذف شده است. برنامه برای جلوگیری از آسیب یا از دست رفتن داده‌های رمزنگاری‌شده، از بالا آمدن خودداری می‌کند.
- **راه‌حل:** نسخه پشتیبان `secrets.json` را بازگردانید یا اگر قصد شروع کاملا مجدد دارید، متغیر `RESET_SECRETS=true` را قرار دهید تا دیتابیس و کلیدها از نو ساخته شوند.
